# PHASE 1 IMPLEMENTATION PLAN

## Overview
This document is the authoritative execution document for the Phase 1 sprint, integrating findings from the P1 Stabilization Audit and newly approved workstreams. The goal is to ensure a user can successfully navigate: Homepage → Run AI Audit → Receive Results → Download PDF → Submit Contact Form, with no broken flows.

## Workstreams & Execution Scope

### A. Frontend Stability & Workflow Independence
*   **P1 Workflow UI Coupling:** Decouple `NewWorkflow.tsx` from requiring an `auditId`. The Workflow Diagnostic must be accessible independently.
*   **P2 AuthStore TS Errors:** Fix TypeScript warnings in `frontend/src/store/authStore.ts` to ensure clean builds.

### B. AI Audit Engine & Results Generation
*   **Scoring Verification:** Verify that the score, findings, and recommendations are actually reliably generated by the backend and not just mocked or failing. Fix backend processing if necessary.
*   **Known Limitations Section:** Every generated report (Web and PDF) MUST include the "Assessment Limitations" disclaimer.
*   **Report Structure:** Ensure the Web Report functions and displays the necessary components (Findings, Recommendations, etc.).
*   **JSON type compatibility:** Ensure SQLAlchemy generic `JSON` is used instead of `JSONB` for cross-DB compatibility (as noted in memory directives).

### C. Contact Form & Lead Storage
*   **Database:** Create `contact_leads` table via Alembic migration (using `asyncpg` locally without updating `alembic_version` table when applying raw SQL manually if needed).
    *   Schema: `id`, `name`, `email`, `company`, `interest`, `message`, `status`, `notes`, `source_page`, `created_at`.
*   **API:** Create backend endpoint `POST /api/contact` to accept submissions.
*   **Frontend:** Ensure the contact form (`/contact`) correctly submits data to the backend.

### D. Navigation & Route Resiliency
*   **Unimplemented Features (Forecasting, Benchmarking):** Must not use dead links. Route to the contact form (`/contact?interest=...`) with pre-filled context.
*   **Forecasting Constraint:** Forecasting remains a "Risk Projection Layer" inside AI Audit and Workflow Diagnostic. Do NOT create standalone forecasting routes or product flows.
*   **Legal Pages:** Ensure Privacy Policy and Terms of Service links exist and do not 404 (create simple placeholder pages if necessary).

### E. Sample Report (Workstream G) - P0
*   **Purpose:** Allow prospects to understand the deliverable before running an assessment.
*   **Access:** Must be accessible from the Homepage and the AI Audit page.
*   **Implementation:** MUST NOT BE STATIC. Create a "Sample Organization", run it through the Deterministic Engine, and generate a Sample Audit using the same pipeline as real audits to test the workflow and prevent report drift.

### F. PDF Export (P2 PDF Generator Crash)
*   **Scope:** Functional PDF export only. Not visual perfection. Success = PDF generated and downloaded with report content present.
*   **Backend:** Fix `generate_report` function error in `pdf_generator.py` using `ReportLab`. Ensure the backend API `api/reports/export` works.
*   **Frontend:** Ensure the "Download PDF" button successfully triggers the backend pipeline. Do not use client-side PDF generation.

### H. User Journey Verification
*   **Requirement:** After EVERY workstream execution, run the full core journey: Homepage → Run Audit → Results → Download PDF → Contact.
*   **Deliverable:** Document whether the journey passes, fails, or partially passes before moving to the next workstream.

## Implementation Order
1.  **Frontend Stability (Workstream A):** Decouple Workflow UI and fix TS errors.
2.  **AI Audit Engine (Workstream B):** Verify deterministic scoring generation and JSON DB types.
3.  **Results Generation (Workstream B):** Add Known Limitations text and ensure Web Report renders correctly.
4.  **Contact Form (Workstream C):** DB migration (with expanded schema), API, and frontend integration.
5.  **Navigation (Workstream D):** Route unimplemented features to contact flow.
6.  **Legal Pages (Workstream D):** Setup legal placeholders.
7.  **Sample Report (Workstream E):** Generate dynamic sample report via backend pipeline.
8.  **PDF Export (Workstream F):** Fix backend Python crash and verify functional download.

## Expected Artifacts

*   **New Files:** `alembic/versions/xxxx_create_contact_leads.py`, Legal page TSX files, Sample Report implementation.
*   **Database Changes:** New `contact_leads` table, SQLAlchemy `JSONB` -> `JSON` model changes.
*   **Backend API Changes:** New `POST /api/contact` endpoint. Fix in `pdf_generator.py`.
*   **Frontend Route Changes:** `/contact` logic updated, `/sample-report` added, Workflow Diagnostic decoupled.

## Risk Review
*   **Database Migrations:** Must use Alembic. Raw SQL should avoid `alembic_version` conflicts per memory. SQLAlchemy JSON compatibility changes.
*   **PDF Generation:** `pdf_generator.py` has a known crash. We must fix the syntax error without over-engineering the styling.
*   **AI Audit Scoring:** We must actively verify the deterministic engine actually computes scores, findings, and recommendations.
*   **API Contract Changes:** Ensure the new Contact API endpoint is properly mapped.
*   **Sample Report Realization:** Generating a report dynamically via the engine requires the engine to be fully stable.
