# PDF Export Backend Modernization Guide

## Objective
To align the existing backend PDF export pipeline with the new "Consulting Deliverable" UI standard established in Phase 1 (Frontend UX Transformation).

## Current Architecture
The current PDF export relies on the backend `api/reports/export` endpoint. The frontend invokes this endpoint to trigger a job, polls for the status, and eventually provides the user a `download_url`.

## Required Backend Adjustments

### 1. Document Structure Modifications
The generated PDF layout must abandon any dashboard-like charts (e.g. radar charts, metric heavy tables) and adopt a text-heavy, report-oriented structure.

#### Expected Page 1: Cover Page
- **Logo:** TarkaX organizational logo (left or center aligned)
- **Organization Details:** Company Name, Contact/Scope
- **Report Title:** "AI Readiness Diagnostic"
- **Metadata:**
  - Date Generated (e.g. "January 14, 2025")
  - Version (e.g. "1.0")
- **Executive Summary Block:** Include the final AI Maturity Score (e.g., 72/100) along with a succinct written verdict (e.g., "Moderate adoption with significant governance weaknesses").

#### Expected Page 2: Findings
- **Layout:** Remove bulleted lists. Replace them with numbered finding blocks.
- **Content:**
  - Title of finding
  - One-sentence explanation
  - Severity Level (Critical, Major, Advisory) - styled appropriately in the PDF output.

#### Expected Page 3: Recommendations
- **Layout:** Structured format mapping directly to the frontend's `RecommendationCard`.
- **Content:** For each recommendation, provide:
  - Required Action
  - Rationale
  - Desired Future State

#### Expected Page 4 (Final Page): Sign-off
- **Footer Text:** "Generated by TarkaX Operational Intelligence Platform"
- Keep this page minimal and strictly text-based.

### 2. Styling Instructions for the PDF Generator
If the backend is using a tool like ReportLab, wkhtmltopdf, or Headless Chrome:
- **Fonts:** Utilize `IBM Plex Sans` for standard text and `IBM Plex Mono` specifically for scores, data points, and metadata.
- **Colors:** Transition from soft dashboard colors to a stark enterprise palette:
  - Background: White (`#FFFFFF`)
  - Primary Text: Slate/Navy (`#0F172A`)
  - Secondary Text: Slate (`#475569`)
  - Borders: Light Grey (`#E2E8F0`)
- **Spacing:** Use substantial whitespace (padding and margins) between sections to mimic a well-crafted physical report.

### 3. API Payload Preservation
No changes are strictly necessary to the `Audit` model schema or the incoming JSON payloads for `export`, provided the backend generator script is updated to pull the right fields (e.g., pulling `contradictions` into the Findings section).

---

By implementing these structural and styling updates in the backend PDF generator, the downloaded artifact will perfectly mirror the new frontend visual language, ensuring the user feels like they are receiving a consultant's report rather than a software dashboard snapshot.
