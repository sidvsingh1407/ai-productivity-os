## Runtime Tests Executed
Due to `alembic upgrade head` failing locally on SQLite (due to `JSONB` incompatibility in an older migration for `billing_plans`), the runtime tests bypassed Alembic and explicitly initialized the tables using `Base.metadata.create_all`.

A specialized verification script (`test_export_flow.py`) was created and executed to test the updated implementation without Celery/Redis dependencies.

### Scenarios Exercised:
1. **Export Job Creation**: Verified that requesting a PDF export correctly creates an `ExportJob` record with status `pending`, saving both the `audit_id` and `org_id`.
2. **Export Job Lookup**: Verified that looking up a job by `job_id` succeeds and returns the correct `audit_id`.
3. **PDF Generation Task**: Manually invoked `_generate_pdf_async` to simulate the background worker. This successfully fetched the audit using `uuid.UUID(audit_id)`, generated the PDF, and saved a `Report` record.
4. **Status Endpoint**: Verified the task execution successfully updated the `ExportJob` status from `pending` to `complete`.
